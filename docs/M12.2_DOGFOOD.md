# M12.2 Smart Router dogfood

Date: 2026-08-14

This is local evidence for M12.2. It is a local milestone PASS, not a public
release, Planner acceptance, or production-readiness claim.

## Scope

- Pi `0.84.1`, Node.js `v22.23.0`, and disposable injected configuration and
  Pi-agent roots.
- The secure Pi auth bridge was used only to inject an in-memory 9Router
  credential into isolated processes. The credential value was never printed,
  persisted, or committed.
- No live Pi configuration, provider account, Keychain entry, tag, push, npm
  publication, or GitHub release was modified.
- The live audit stayed within the mission's bounded triage-request budget;
  readiness-race attempts were discarded and are not acceptance evidence.

## Offline and deterministic evidence

| Case | Result |
|---|---|
| Clear explanation/question | Local `NORMAL`; no recommendation banner and no AI call |

| Telemetry | Routing and analyst persistence tests reject raw prompt/transcript/tool/secret-like values and retain bounded metadata only |

## Live route dogfood

The isolated configuration used two enabled catalog-matching routes:

- Primary: `r9-ninerouter-ag-claude-opus-4-6-think-fe2f756e1d848cbb05ca`
- Fallback: `r9-ninerouter-cx-gpt-5-6-luna-a2c6f198d55f63f2b429`

The secure auth check reported `ready`; the catalog probe returned HTTP 200
with 29 entries. A direct Pi-runtime structured probe completed with
`stopReason=stop` in 5.642 seconds and produced the strict shape
`recommendedMode` + numeric `confidence` + array `reasons`.

| Scenario | Observed result |
|---|---|
| English ambiguous | Real Pi TUI showed `Orchestrator recommended`; the routing event recorded `SUGGEST_MISSION`, `ambiguous`, two triage calls, capability-only fallback, selected fallback route, and `run_as_mission`; one draft Mission was persisted |
| Persian ambiguous | Real Pi TUI showed `پیشنهاد ارکستریتور`; the routing event recorded `ambiguous`, two triage calls, selected fallback route, and `run_normally`; the original Persian prompt continued to native Pi input and no Mission was created |
| Primary failure → valid Fallback | The app’s persisted successful fallback events recorded `triageCalls=2`, `fallbackUsed=true`, `triage_fallback`, the fallback route ID, and a valid final decision; fallback is reachable only after a capability-class failure |
| Both routes unavailable | Disposable offline config with missing Primary and Fallback produced two bounded capability checks, `failureClass=unavailable`, a usable recommendation, `cancelled`, and visible original-prompt restoration |
| Simple prompt | Isolated Pi TUI reached the editor with no Smart Routing banner and no triage request |
| Complex prompt | Isolated Pi TUI showed the banner; `Run as Mission` created exactly one draft Mission with matching title/goal |

Persisted routing rows contained only allowlisted decision/path/reason/action,
triage-count/fallback/failure metadata, duration, and (when selected) stable
route ID. No raw prompt, transcript, provider response, credential, or private
endpoint was stored in telemetry.
